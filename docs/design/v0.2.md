# eslint-plugin-nest-drift — v0.2 design: type guards that lie about their type

Date: 2026-09-27
Status: draft, pending review
Branch: `release/0.2` (merged to `main` only after 0.1.x is stable)

## Problem

A user-defined type guard (`(x): x is T => …`) is a promise TypeScript takes on faith. The checker
never verifies that the body actually establishes `T`. In real NestJS codebases guards rarely check
every property; they narrow a union by **one** field:

```ts
const isCircle = (x: unknown): x is CircleShape => (x as { kind?: unknown })?.kind === Kind.Circle;
const isArchived = (d: Draft | Archived): d is Archived => 'archivedAt' in d;
const isV1 = (c: ConfigV1 | ConfigV2): c is ConfigV1 => !('schemaVersion' in c);
```

The bugs we see in practice are guards whose checked field **contradicts the declared type**:

```ts
// checks the Square discriminant but promises the *options* type, which has no `kind` field at all
const isSquare = (x: unknown): x is SquareOptions => (x as { kind?: unknown })?.kind === Kind.Square;
```

Everything after such a guard runs with the wrong type and TypeScript stays silent.

## Goal

Three typed rules that report guards whose checks contradict — or do not establish — the declared
type. Same quality bar as v0.1: zero false positives in `recommended`; when a rule cannot be sure it
stays silent. Must work with `strictNullChecks: false` (common in NestJS services).

## Non-goals (v0.2)

- Assertion functions (`asserts x is T`) and `this is T` predicates.
- Predicates TypeScript infers itself (unannotated `.filter(x => …)` callbacks, TS ≥ 5.5): the checker
  already verifies those.
- Guards built from `switch`, `if` chains returning `true`/`false`, or boolean variables: they yield no
  analysable conjuncts and are silent by construction (accepted false negatives).
- Runtime-validation libraries (zod, class-validator): a guard that delegates to them is skipped.

## Terms

- **Guard**: a function declaration, function expression, arrow function or method **with a body**
  and an **explicit return type annotation** that is a `TSTypePredicate` `p is T` (no `asserts`, not
  `this`). Unannotated functions are skipped even when TypeScript infers a predicate for them. Overload signatures, `declare function`,
  abstract / interface methods and `.d.ts` declarations have no body and are skipped by all rules.
- **The parameter `p`** is the function's own parameter whose name equals the predicate's parameter
  name (`AssignmentPattern` → its `.left`; `RestElement` → guard skipped; a `this` parameter is never
  `p`). Its references are resolved through the scope manager, so shadowing is handled. A guard that
  writes to `p` is skipped by all rules.
- **Aliases of `p`**: a `const` declared in the guard body and initialised with `p` (possibly wrapped),
  never written afterwards, is treated as `p` itself by all rules (`const o = x as Record<string, unknown>`).
- **Checked expressions**: for an arrow with an expression body, the body; otherwise the argument of
  every `return` statement belonging to the guard (not to nested functions), including literal
  `true` / `false`. Each conjunct of a `&&` chain is a necessary condition for *that* `return` to yield
  `true`, which is all `missingProperty`, `valueMismatch` and `requiredButExcluded` rely on
  (`notDiscriminating` needs sufficiency and is restricted separately); a `false` literal yields no checkable conjuncts.
- **Conjuncts**: each checked expression split on `&&`. A conjunct that is itself `||`, `??` or a
  conditional is **opaque**: it is ignored (the remaining conjuncts are still necessary conditions)
  and it prevents the "all conjuncts are …" test in `notDiscriminating`.
- **Wrappers** unwrapped around `p`: `TSAsExpression`, `TSTypeAssertion`, `TSNonNullExpression`,
  `TSSatisfiesExpression` (typescript-estree has no parenthesis nodes). `ChainExpression` is unwrapped
  around the access itself (`P?.k`).
- **Parameter access of `k`**: `P.k`, `P?.k`, `P['k']` (string literal key) where `P` is `p` possibly
  wrapped. `p.a.b` is not an access of `b` — the object must be the parameter itself.
- **Target members**: the non-nullish union constituents of `T`.
- **Shaped member**: a member with `TypeFlags.Object` (or an intersection of object types), other than
  the lib `Object` type, whose `getProperties()` is non-empty (inherited included) or that has an index
  signature. A member that is not shaped is **shapeless**. Rules 1 and 2 are
  silent unless **every** target member is shaped — `object`, `{}`, primitives, literals and enum
  members all make them silent.
- **Member has `k`**: looked up with `checker.getPropertyOfType(member, k)` (which includes inherited
  and apparent members such as `toString` / `constructor`), never by scanning `getProperties()`.
- **Member admits `k` by index**: `checker.getIndexInfosOfType(member)` has an info whose key type
  accepts `checker.getStringLiteralType(k)`, or `checker.getNumberLiteralType(Number(k))` for numeric
  keys (`'0' in arr`). Such a member counts as "has `k`" with an uncheckable type.
- **Ignored properties**: rule option `ignoreProperties: string[]` for rules 1 and 2, default
  `['__typename', '__t', '_tag']` — runtime discriminators that frameworks add without declaring them
  (GraphQL, Mongoose discriminators, tagged unions). Guards on these are never reported.

## Rules

### `guard-discriminant-matches-type` — recommended

Considers conjuncts `A === V` and `V === A` (strict equality only; `==`, `!==`, `!=` are ignored)
where `A` is a parameter access of `k` and `V` has a **unit literal type**: string / number / bigint
literal, boolean `true` / `false`, or enum literal type. `null`, `undefined` and `void 0` are not unit
values here (they test absence, not a discriminant).

Reports on the conjunct when:
- `missingProperty`: no target member has `k` (declared or admitted by index).
- `valueMismatch`: **every** target member has `k`, and for every member `V` is not value-assignable to
  any constituent of the member's `k` type (`isCoveredBy(V, constituents(kType))` is false). Values are
  compared at runtime level, so `'open'`, `Status.Open = 'open'` and `` `${Status}` `` agree.

Silent when: `T` or a member is uncheckable (any / unknown / type parameter) or shapeless; a member's
`k` type is uncheckable (including index-admitted, when `k` is not declared) or contains a branded
primitive (`string & { __brand }`, which holds plain literals at runtime); `k` is in `ignoreProperties`.

### `guard-in-check-matches-type` — recommended

Considers conjuncts `'k' in P` and `!('k' in P)`.

Reports (on the conjunct, except `notDiscriminating`):
- `missingProperty` (for `'k' in p`): no target member declares or admits `k` (optional counts).
- `requiredButExcluded` (for `!('k' in p)`): every target member declares `k` as required.
- `notDiscriminating` — reported once, on the return type predicate, when all hold:
  - the guard body is a single expression (expression-bodied arrow, or a block whose only statement
    is `return <expr>`); any other statement — early return, `if`, `throw`, loop — makes it silent;
  - the parameter's declared type has at least two non-nullish object-type constituents;
  - every conjunct of every checked expression is a **non-negated** `'k' in p` check (no opaque conjuncts);
  - every such parameter constituent declares each checked `k` as required;
  - at least one parameter constituent is **not assignable to `T`** (otherwise the guard is a harmless no-op).

Silent when: `T` / members uncheckable or shapeless; any member admits a checked `k` by index; `k` in
`ignoreProperties`.

Class fields and runtime absence: a `declare` field is never emitted, and with
`useDefineForClassFields` off (the default below ES2022) a field without an initializer or parameter
property is absent at runtime. For `requiredButExcluded` and `notDiscriminating` such fields are treated
as **optional**, so a `!('k' in x)` / `'k' in x` check on them is never reported.

### `guard-covers-required-properties` — off by default, in `strict`

Applies to guards whose parameter type is `unknown`, `any`, `object`, `{}` or a
`Record<string, unknown>`-like type (string index signature to unknown/any), and whose target has
**exactly one** non-nullish member that is a shaped object type. Lib-declared types (`Error`, `Date`,
…), arrays and tuples are excluded.

A **required property** is a property symbol that is not optional, not a method, not an accessor,
not symbol-keyed and not `private` / `protected` / `#private`.

A property `k` is **touched** when the guard body contains, on `p` (possibly wrapped): a parameter
access of `k`, `'k' in p`, a destructuring of `p` binding `k`, or a string-literal `'k'` argument of
`Object.hasOwn(p, 'k')`, `Reflect.has(p, 'k')`, `Object.prototype.hasOwnProperty.call(p, 'k')` or
`p.hasOwnProperty('k')`.

Reports `uncheckedProperties` **once** on the type predicate, listing every untouched required property.

Silent when the guard contains a discriminant check (`p.k === <unit literal>`): that is the
conventional proof of a union member.

Silent (treated as delegation) when: a key is not a string literal (`k in p`, `p[k]` — keys from a
dynamic list); `p` is referenced inside a nested function (`keys.every((k) => k in p)`); `p` is compared
by identity with anything other than `null` / `undefined` (`p === EMPTY`); `p` (possibly wrapped, or an alias) is passed as an argument to any
call other than the four has-own forms above and `Array.isArray(p)` (`Object.keys(p)` still counts as
delegation: it usually drives a dynamic check); any method is
called on `p` other than `hasOwnProperty`; `p` is assigned to a `let` / `var`, or destructured into a
rest element; the body contains
`p instanceof X`; the target has more than `maxProperties` required properties.

Options: `{ maxProperties?: number }` (default 30).

## Configs

- Each rule declares `meta.docs.recommended`; `recommended` / `legacy-recommended` are built from rules
  with `recommended: true`, `strict` / `legacy-strict` from all rules. `plugin.configs` gains the two new
  entries in its type, the plugin test asserts both sets, and the README legend gains a "in `strict`"
  column.
- `recommended`: v0.1 rules + `guard-discriminant-matches-type` + `guard-in-check-matches-type`.
- `strict`: `recommended` + `guard-covers-required-properties`.

## Architecture

- `src/core/guards.ts` — helpers on ESTree + checker:
  - `getTypeGuard(fn, sourceCode, services)` → `{ fn; refs: Set<Node> (parameter and const-alias read references); escapes: boolean (let/var copy or rest destructuring); paramType; target; predicateNode; checked; singleExpression } | undefined`
  - `conjuncts(expr)` → `{ conjunct: TSESTree.Expression; opaque: boolean }[]`
  - `readParamAccess(expr, param)` → property name or undefined
  - `readInCheck(expr, param)` → `{ key: string; negated: boolean } | undefined`
  - `memberHasProperty(member, k, checker, compilerOptions)` → `'declared' | 'required' | 'index' | 'none'`
  - `isShapeless(member, checker)` → boolean
  - `touchedProperties(fn, param)` → `{ touched: Set<string>; delegates: boolean }`
- Rules in `src/rules/guard-*.ts`, one per file, built on `core/guards.ts` and `core/type-compare.ts`.
- `core/index.ts` re-exports the new helpers (experimental API).

## Testing

TDD per rule with RuleTester (strict fixture) and `looseRuleTester` (`strictNullChecks: false`).
Cases:
- cast + optional chaining + enum discriminant (valid), and the wrong-target guard (invalid);
- raw string vs enum property (`x.status === 'open'` with `status: Status`, valid), cross-enum with
  equal values (valid), `` `${Kind}` `` targets (valid);
- `=== undefined`, `== null`, `==` coercions (all silent);
- targets `object`, `{}`, `Record<string, unknown>` (silent); primitive guards `v is string` (silent);
  `Foo | Legacy` where `Legacy` lacks `k` (silent); `'toString' in x` (not missing);
- `__typename` / `__t` / `_tag` (silent by default; reported when `ignoreProperties: []`);
- `.filter((x): x is T => …)` callbacks, methods, several `return`s with early `return false`;
- overload signatures, `declare function`, abstract methods (silent in all three rules);
- `'k' in x`, `!('k' in x)`, `'k' in x && x.flag === true` (not non-discriminating), negated-only
  guards (not non-discriminating), `(x: A | B): x is A | B` (not non-discriminating),
  `if (x.kind !== 'a') return false; return 'k' in x` (not non-discriminating), uninitialised and
  `declare` class fields (not `requiredButExcluded`);
- rule 3: union target (silent), class target with methods (methods not required), `Error` / array
  targets (silent), alias `const o = x as Record<string, unknown>; o.a` (touches `a`),
  `typeof x === 'object' && !Array.isArray(x) && 'a' in x` (not delegation), `Object.hasOwn(x, 'k')` (touches `k`),
  delegation to another function (silent), single report listing all missing properties.

## Release

`minor` changeset → 0.2.0. Rule docs under `docs/rules/`, each with a "When not to use it" section
(rule 1/2: undeclared runtime discriminators → `ignoreProperties`). If rule 3 delays the release, it
ships in a later minor release (adding a rule to `strict` is a `minor` change).
