# eslint-plugin-nest-drift — v0.2 design: type guards that lie about their type

Date: 2026-09-27
Status: draft, pending review
Branch: `release/0.2` (merged to `main` only after 0.1.x is stable)

## Problem

A user-defined type guard (`(x): x is T => …`) is a promise TypeScript takes on faith. The checker
never verifies that the body actually establishes `T`. In real NestJS codebases guards rarely check
every property; they narrow a union by **one** field:

```ts
const isFoo = (x: unknown): x is FooEntity => (x as { type?: unknown })?.type === Kind.Foo;
const isSkip = (r: Plan | Skip): r is Skip => 'skipped' in r;
const isLegacy = (e: Current | Legacy): e is Legacy => !('field1' in e);
```

The bugs we see in practice are guards whose checked field **contradicts the declared type**:

```ts
// checks the Bar discriminant but promises the *conditions* type, which has no `type` field at all
const isBar = (x: unknown): x is BarConditions => (x as { type?: unknown })?.type === Kind.Bar;
```

Everything after such a guard runs with the wrong type and TypeScript stays silent.

## Goal

Three typed rules that report guards whose checks contradict — or do not establish — the declared
type. Same quality bar as v0.1: zero false positives in `recommended`; when a rule cannot be sure it
stays silent. Must work with `strictNullChecks: false` (common in NestJS services).

## Non-goals (v0.2)

- Assertion functions (`asserts x is T`) and `this is T` predicates.
- Guards whose return expression is not a plain `&&` chain (any `||`, ternary, or a boolean variable) — skipped.
- Runtime-validation libraries (zod, class-validator) — out of scope; a guard delegating to them is skipped.

## Terms

- **Guard**: a function declaration, function expression, arrow function or method whose return type
  annotation is a type predicate `p is T` where `p` is one of its parameters (`asserts` excluded).
- **Checked expressions**: for an arrow with expression body, the body; otherwise the argument of every
  `return` statement in the function (not nested functions). A guard is analysed only if every checked
  expression is analysable; otherwise it is skipped.
- **Conjuncts**: a checked expression split on top-level `&&` (parentheses unwrapped). A checked
  expression containing `||`, `??` or a conditional at top level is not analysable.
- **Parameter access**: an expression that reads property `k` of the guard parameter `p` — `p.k`,
  `p?.k`, `p['k']` (string literal), where `p` may be wrapped in parentheses, `as` / `<T>` casts and
  non-null assertions (`(p as { k?: unknown })?.k`).
- **Target members**: the non-nullish union constituents of `T`.

## Rules

### `guard-discriminant-matches-type` — recommended

Considers conjuncts `A === V`, `V === A`, `A == V`, `V == A` where `A` is a parameter access of `k`
and `V` has a unit type (string / number / boolean literal, enum member, `null` excluded).

Reports on the conjunct when:
- `missingProperty`: no target member has property `k`.
- `valueMismatch`: at least one target member has `k`, and for **every** target member that has `k`,
  `V` is not value-assignable to that member's `k` type (`isValueAssignable` from `core/type-compare`,
  so `Kind.Foo = 'foo'` and `'foo'` compare equal).

Silent when: `T` or a member is uncheckable (any / unknown / type parameter); a member's `k` type is
uncheckable; `V` is not a unit type; `T` has an index signature that would admit `k`.

### `guard-in-check-matches-type` — recommended

Considers conjuncts `'k' in P` and `!('k' in P)` (`P` = the parameter, possibly wrapped as above).

Reports:
- `missingProperty` (for `'k' in p`): no target member declares `k` (optional counts as declared).
- `requiredButExcluded` (for `!('k' in p)`): every target member declares `k` as **required**.
- `notDiscriminating`: the parameter's declared type is a union of object types, **every** conjunct
  of the guard is an `in` check, and every union member of the parameter type declares each checked
  `k` as required — so the guard is true for every member and narrows nothing.

Silent when: `T` / members uncheckable; any member has an index signature; for `notDiscriminating`,
the parameter type is `unknown` / `any` / not a union.

### `guard-covers-required-properties` — off by default, in `strict`

For guards whose parameter type is `unknown` or `any` and whose target members are object types:
every required property of every target member must be *touched* by the guard — appear as a parameter
access, an `'k' in p` check, or a destructured binding of `p` — anywhere in the guard body.

Reports `uncheckedProperty` once per missing property, listing it by name.

Silent when: the parameter is passed as an argument to any call in the body (delegation: zod, a
validator, another guard); the body contains `p instanceof X` (the class check establishes the shape);
a member is a `Record` / has an index signature; `T` has more than 30
required properties (option `maxProperties`, default 30).

Option: `{ maxProperties?: number }`.

## Configs

- `recommended` and `legacy-recommended`: add the two recommended rules.
- New `strict` (flat) and `legacy-strict` (eslintrc): everything in `recommended` plus
  `guard-covers-required-properties`.

## Architecture

- `src/core/guards.ts` — pure helpers on ESTree + checker:
  - `getTypeGuard(fn, services)` → `{ param: TSESTree.Identifier; paramType: ts.Type; target: ts.Type; checked: TSESTree.Expression[] } | undefined`
  - `conjuncts(expr)` → `TSESTree.Expression[] | undefined` (undefined = not analysable)
  - `readParamAccess(expr, paramName)` → property name or undefined (handles `?.`, casts, `!`, parens, `['k']`)
  - `readInCheck(expr, paramName)` → `{ key: string; negated: boolean } | undefined`
  - `touchedProperties(fn, paramName)` → `Set<string>` and `delegates: boolean`
- Rules in `src/rules/guard-*.ts`, one per file, built on `core/guards.ts` and `core/type-compare.ts`.
- `core/index.ts` re-exports the new helpers (experimental API).

## Testing

TDD per rule with RuleTester (strict fixture) and `looseRuleTester` (`strictNullChecks: false`).
Cases, all with neutral names:
- the cast + optional chaining + enum discriminant shape (valid, and the wrong-target bug as invalid);
- string / numeric enums, string literal unions, `` `${Kind}` `` targets;
- `.filter((x): x is T => …)` callbacks, methods, function declarations with several `return`s;
- `'k' in x`, `!('k' in x)`, `'k' in x && x.flag === true` (not reported as non-discriminating);
- `Record<string, unknown>` / JSON-object guards (silent), primitive guards `v is string` (silent),
  generic `T` (silent), `||` bodies (silent), delegation to another function (silent for rule 3).

`minor` changeset → 0.2.0. Rule docs under `docs/rules/`. README rules table gains the three rules and
the `strict` config.
