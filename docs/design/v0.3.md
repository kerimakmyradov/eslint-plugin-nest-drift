# eslint-plugin-nest-drift — v0.3 design: entities, columns and DTO mapping

Date: 2026-09-27
Status: implemented
Branch: `release/0.3` (merged to `main` only after 0.2 ships)

## Problem

In NestJS + TypeORM services a value crosses type boundaries that TypeScript never compares:

1. **Database → entity.** The column type decides what the driver returns; the TypeScript property type
   is only a promise. `@Column({ type: 'decimal' }) amount: number` compiles, but PostgreSQL (and MySQL)
   return `numeric` as a **string**, so `amount + fee` concatenates.
2. **Entity → DTO.** Response DTOs are usually hand-written classes filled with
   `plainToInstance(FooDto, entity)`. The call accepts anything, so a DTO field typed `number`
   happily receives the entity's `string`, and a field renamed in the entity silently becomes `undefined`.
3. Nullability: `nullable: true` columns typed without `| null`.

## Goal

Two typed rules for these boundaries, same bar as before: zero false positives in `recommended`,
silent when unsure, correct with `strictNullChecks: false`. Verified against TypeORM 0.3.28 and 1.1.1,
`pg` / `pg-types` defaults and class-transformer 0.5.1.

## Non-goals (v0.3)

- ORMs other than TypeORM (Prisma types are generated, MikroORM / Mongoose — later, on demand).
- Relations (`@ManyToOne` etc.), embedded entities, view entities.
- `instanceToPlain`, `classToPlain`, manual mappers (`toDto()` functions).

## Rule 1: `column-matches-type` — recommended

Checks TypeORM column decorators (imported from `typeorm`, resolved through the checker like v0.1
decorators) against the TypeScript type of the property.

### Column type resolution

- `@Column('decimal', { … })`, `@Column({ type: 'decimal', … })`, `@Column({ type: Number })`
  (lib constructors `String`, `Number`, `Boolean`, `Date`). No type given → silent (TypeORM derives it
  from the TypeScript type). Any other function or class (`@Column(() => Address)` embedded, `Buffer`)
  or a non-literal first argument → silent.
- `@PrimaryColumn(type?, options?)` — same as `@Column`.
- `@PrimaryGeneratedColumn()` / `('increment')` / `('identity')` → `integer` unless an options object
  (first or second argument) sets `type` (`@PrimaryGeneratedColumn({ type: 'bigint' })` is common);
  `('uuid')` → `uuid`; `('rowid')` → silent.
- `@CreateDateColumn`, `@UpdateDateColumn`, `@DeleteDateColumn` → `timestamp` unless `type` is set;
  `@VersionColumn` → `integer` unless `type` is set.
- A `transformer` option (any value) → silent.
- A column whose property name equals the `name` of a sibling `@JoinColumn({ name })` in the same class
  → silent (TypeORM overwrites its type with the referenced column's type).

### Runtime kind of a column type (TypeORM 0.3 / 1.x with `pg` / `mysql2` defaults)

| Column types (case-insensitive) | Scalar | With `array: true` (PostgreSQL) |
|---|---|---|
| `int`, `int2`, `int4`, `integer`, `smallint`, `tinyint`, `mediumint`, `float`, `float4`, `float8`, `double`, `double precision`, `real` | `number` | `number` |
| `decimal`, `numeric`, `dec` | `string` (option `decimal`) | `number` |
| `money` | `string` | `string` |
| `bigint`, `int8` | option `bigint` (default: not checked) | same as scalar |
| `varchar`, `character varying`, `char`, `character`, `nvarchar`, `nchar`, `text`, `tinytext`, `mediumtext`, `longtext`, `uuid`, `inet`, `cidr`, `macaddr`, `time`, `timetz`, `time with time zone`, `time without time zone` | `string` | `string` |
| `citext` | `string` | silent (unregistered array type) |
| `date` | `string` (TypeORM returns `YYYY-MM-DD`) | `date` |
| `timestamp`, `timestamptz`, `timestamp with time zone`, `timestamp without time zone`, `datetime`, `datetime2` | `date` | `date` |
| `bool`, `boolean` | `boolean` | `boolean` |
| `enum`, `simple-enum` | enum check (below) | enum check on the element |
| `json`, `jsonb`, `simple-json`, `bytea`, `blob`, `interval`, `hstore`, `simple-array`, spatial, anything else | silent | silent |

With `array: true` the property must be an array; its element type is compared.

### Reports

- `columnKindMismatch`: **none** of the property's non-nullish kinds (v0.1 `kindsOf`; branded
  primitives count as their primitive) equals the column's runtime kind. An over-wide
  `amount: number | string` (a read/write model) is accepted. Example message:
  "`decimal` columns are read as strings, but `amount` is typed as `number`."
- `columnEnumMismatch`: `{ type: 'enum', enum: E }` where the property type and `E` disagree — the
  shared `isEnumMismatch` helper also used by `enum-matches-type`.
- `nullableWithoutNull` (only with `strictNullChecks`): `nullable: true` (or `@DeleteDateColumn`, which
  is nullable by default) while the property type has no `null`.
- `nullOnNotNullColumn` (only with `strictNullChecks` and option `reportNullOnNotNull: true`): the type
  includes `null` but the column is not nullable. Off by default: an over-wide type is not a runtime bug.

Silent when: the property type is `any` / `unknown` / generic; the relevant option is not a literal
(read with `readBooleanOption`; `unknown` → silent).

### Options

```ts
{
  decimal?: 'string' | 'number';          // default 'string'; 'number' if you parse numerics (pg OID 1700, mysql2 decimalNumbers)
  bigint?: 'off' | 'string' | 'number';   // default 'off'; the linter cannot see pg.types.setTypeParser(20, …)
  reportNullOnNotNull?: boolean;          // default false
  timestamp?: 'date' | 'string';          // default 'date'; 'string' for MySQL with dateStrings: true —
                                          // applies only to explicitly typed timestamp / timestamptz columns
                                          // (MySQL re-parses datetime into Date; date-column defaults are datetime there)
}
```

## Rule 2: `plain-to-instance-matches-source` — recommended (`missingInSource` via option / `strict`)

### Calls

`plainToInstance(Dto, source, options?)` and the deprecated `plainToClass`, imported from
`class-transformer` (resolved through the checker). `Dto` must resolve to a non-generic class.

`options`: when present it must be an object literal whose keys are only `excludeExtraneousValues`,
`exposeUnsetFields`, `enableCircularCheck`, `strategy` and `enableImplicitConversion`, with literal
values; otherwise the call is skipped (`groups`, `version`, `exposeDefaultValues`, `targetMaps` … change
which keys are copied).

`source`: its type's non-nullish constituents; arrays and tuples are replaced by their element types.
Every constituent must be an object type with declared properties and no index signature, not
`any` / `unknown` / a type parameter; otherwise the call is skipped.

### Which DTO properties are compared

Data properties of the DTO instance type (not methods, accessors, static, private or protected
members). For each property, class-transformer decorators are collected from the same-named property
declarations in the DTO class **and its base classes** (class-transformer looks property metadata up
through ancestors). A property is skipped when it has `@Exclude()`, `@Transform(...)`, `@Type(...)`, or
`@Expose()` with `name`, `groups`, `since`, `until` or `toPlainOnly` (not exposed for `plainToInstance`: in expose mode never copied, otherwise copied only if the source has the key); or when it has no declaration (mapped types).

**Expose mode** (only exposed properties are copied): a class-level `@Exclude()` on the DTO class
itself (class-level strategy is **not** inherited), `excludeExtraneousValues: true`, or
`strategy: 'excludeAll'`. In expose mode, properties without `@Expose()` are skipped.

A property assigned on the result afterwards — `const dto = plainToInstance(Dto, e); dto.amount = …`
in the same function — is skipped; if the result is passed to `Object.assign`, the call is skipped.

### Reports (on the call)

- `missingInSource` — only with option `checkMissing: true` (enabled by the `strict` configs), only in expose mode, only when every source constituent is a **class instance**
  type (an entity; object-literal and interface sources are often partial payloads by design), and only
  for required DTO properties (no `?`, and no initializer when the call passes `exposeUnsetFields: false`,
  which keeps the initializer): no constituent has the property.
  "`FooDto.accountId` is exposed, but `FooEntity` has no `accountId`: it is always `undefined`."
- `kindMismatch`: comparing only `string`, `number`, `boolean`, `bigint`, the source property's
  non-nullish kinds and the DTO property's kinds are **disjoint**. `date` ↔ `string` is not reported
  (dates serialise to strings), objects / arrays / uncheckable types are not compared, numeric enums
  are `number`, string enums are `string`. Silent when `enableImplicitConversion` is present.

### Options

```ts
{ checkMissing?: boolean } // default false; the strict configs pass { checkMissing: true }
```

A trial on a real codebase showed the common pattern "map the entity, then fill computed fields
elsewhere" (e.g. in the controller); such fields are exposed but not in the entity by design, so
`missingInSource` is opt-in.

## Configs

`recommended` gets both rules with default options. `strict` / `legacy-strict` get every rule; rules
listed in a `STRICT_OPTIONS` table in `src/index.ts` are configured as `['error', options]` there
(`plain-to-instance-matches-source`: `{ checkMissing: true }`).

## Architecture

- `src/core/typeorm.ts`: `columnInfo(decorator, services)` → `{ decorator; typeName; kind; arrayKind; array; nullable: OptionState; enumNode?; hasTransformer }` with the table above as data.
- `src/core/ts-decorators.ts`: decorators on **TypeScript** declarations (for DTOs in other files):
  `getTsDecorators(declaration, checker)` → `{ name; module; call }[]`, `tsObjectOption(call, key)`.
- `src/core/type-compare.ts`: `isEnumMismatch(checked, allowed, checker, annotated)` shared by
  `enum-matches-type` and `column-matches-type`.
- `src/rules/column-matches-type.ts`, `src/rules/plain-to-instance-matches-source.ts`.

## Testing

- Fixture dev dependency: `typeorm` (types only); a cross-file DTO fixture `tests/fixtures/dtos.ts`.
- Rule 1: every scalar and array row; `decimal` on `number` (invalid), on `string` and `number | string`
  (valid), `decimal` array on `number[]` (valid); `date` on `Date` (invalid) and `date` array on `Date[]`
  (valid); `timestamptz` on `Date`; `@PrimaryGeneratedColumn({ type: 'bigint' }) id: string` (valid);
  `('uuid')` on `number` (invalid); transformer, embedded, `Buffer`, shared options, join columns (silent);
  enum columns; all option values; nullability under strict and loose fixtures.
- Rule 2: expose / non-expose; base-class `@Exclude()` not inherited; inherited property decorators;
  `@Expose({ name | groups })`, `@Transform`, `@Type` (silent); unsupported options (silent); missing
  field from an entity (invalid) vs from an object literal / interface / optional DTO field (silent);
  decimal `string` into `number` (invalid); `number | string` into `number` (valid); numeric enum →
  `number`, `Date` → `string` (valid); string enum → `number` (invalid); arrays; post-assignment and
  `Object.assign` (silent); cross-file DTO.
- Trial run, read-only, against a real NestJS + TypeORM monorepo before release: zero false positives
  in `recommended`.

## Release

`minor` changeset → 0.3.0. Rule docs with "When not to use it" (custom type parsers → `decimal` /
`bigint` options; DTOs filled by manual mappers).
